# Plan Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Issue #15. A `plan` tool the main agent calls with its whole checklist (items with `pending`/`in_progress`/`done`), held by the session, saved with it, re-injected after compaction, pinned above the prompt in the TUI, and measured by an eval with the tool on and off.

**Architecture:** One new tool (`src/tools/plan.ts`) that writes through a `ToolContext.plan` host only the main agent gets. `MarvSession` holds the items, saves and restores them (`SavedSession.plan`), passes them to `compactedHistory`, and drops them on `clear()`. `SessionInit.plan` (SDK `plan`, eval `--plan`) leaves the spec out for a whole session. The App pins `PlanView` from `tool_end`'s screen-only `result.plan`. Nothing changes the system prompt or specs mid-conversation.

**Tech Stack:** Bun, TypeScript, zod, Ink, `bun:test`, `ink-testing-library`.

Spec: `docs/superpowers/specs/2026-10-13-plan-tool.md` (to be approved; its open questions decide Task 8's budget and whether Task 5 gets a config switch). Branch: `s4/15-plan-tool`.

**Background for the engineer:**
- Read `CLAUDE.md` first: **Agent loop**, **Session**, **Tools**, **Prompt cache**, **Compaction**, **Sessions**, **Rendering**, **Evals**.
- **Rules tests guard:** every request extends the previous one exactly (`tests/agent.test.ts`): the plan never changes the system prompt or the specs; `ToolResult.plan`, like `diff`, never reaches the model or a trajectory; subagents never get the tool.
- **Conventions:** `.ts` extensions in imports, `import type` for types, comments say *why*. Tests offline: `ScriptedProvider` (`tests/fake-provider.ts`).
- **Commands:** `bun test <path substring>`, `bun test -t "<name>"`, `bun run typecheck`, `bun test`.
