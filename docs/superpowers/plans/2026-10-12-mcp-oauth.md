# MCP OAuth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Issue #18. A remote MCP server that asks for an OAuth login can be logged in to with `/mcp login <server>`: Marv opens the browser (or shows the link and takes a pasted callback address), receives the code on a loopback listener, stores the tokens privately, and the MCP SDK refreshes them. Nothing but the user's command ever starts a login, and no token reaches the model, the transcript, trajectories or a sandboxed command.

**Architecture:** Two new modules. `src/mcp/oauth-store.ts` is the file (`~/.marv/mcp-tokens.json`, `writePrivate`, zod-checked, keyed by owner + URL). `src/mcp/oauth.ts` holds the SDK's `OAuthClientProvider` (`McpOAuthProvider`, passive or interactive), the callback listener and its checks, the browser opener and `probeLogin`. `McpManager` gains the `needs-login` state, connects HTTP servers with or without a provider, and gets `login(name, ui)` / `logout(name)`. `/mcp login|logout` are new command actions the App runs outside turns. `config.ts` gains an optional `oauth` block; the SDK and `cli.tsx` pass the store; the SDK warns about servers that need a login.

**Tech Stack:** Bun, TypeScript, zod, `@modelcontextprotocol/sdk` 1.32 (`client/auth.js`, `StreamableHTTPClientTransport`'s `authProvider` and `finishAuth`), `bun:test`.

Spec: `docs/superpowers/specs/2026-10-12-mcp-oauth.md` (to be approved; its open questions decide Task 8's README text and whether `oauth.scope` exists). Branch: `s3/18-mcp-oauth`, **rebased on #6** (`/mcp add`), which changes the same manager and `/mcp` command.

**Background for the engineer:**
- Read `CLAUDE.md` first: **MCP servers**, **Private files**, **Sandbox**, **Tools** (approval), **Session**, **SDK**, and **Prompt cache**.
- **The SDK's flow** (read `node_modules/@modelcontextprotocol/sdk/dist/esm/client/auth.js`, `auth()` and `authInternal()`, and `streamableHttp.js`, `_authThenStart`, `send`, `finishAuth`): a 401 → `auth(provider)` → cached discovery or RFC 9728 discovery → `clientInformation()` or dynamic registration (`saveClientInformation`) → refresh if `tokens().refresh_token` → else `startAuthorization` + `saveCodeVerifier` + `redirectToAuthorization(url)` and `connect()` throws `UnauthorizedError`. `finishAuth(code)` exchanges the code. `redirectUrl` undefined means a non-interactive grant: always define it. `invalid_grant` → `invalidateCredentials("tokens")` then one retry.
- **Rules that tests guard:** a background connection (startup, tool calls, the SDK) never redirects and never registers; only `/mcp login` does. Errors the model sees are Marv's own sentences. New tools after a login go through `rebuild()` exactly like `/mcp trust`'s (the cache rule).
- **Conventions:** `.ts` extensions in imports, `import type` for types, comments say *why*. Tests never hit the network: `Bun.serve` fixtures only.
- **Commands:** `bun test <path substring>`, `bun test -t "<name>"`, `bun run typecheck`, `bun test` (whole suite).
